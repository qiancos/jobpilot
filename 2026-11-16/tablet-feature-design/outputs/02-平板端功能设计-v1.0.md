> 输入：`boss/PRD-投递驾驶舱-v1.0.md`、`boss/STATUS.md`、`boss/WORKFLOW.md`、`boss/screening-criteria.md`、`jobpilot/README.md`、`01-标杆拆解-UPCV.md`

> 日期：2026-11-16

## 0. 一页纸结论

UPCV 在电脑上做的是「**替你想 + 替你写 + 你确认后替你填**」。平板端要做的是同一件事，但把「填」换成「**替你在 BOSS App 里点、发、核验**」：

```
UPCV：搜索 → 匹配分 → 定制简历 → 生成招呼 → 确认 → 代填/发送 → 看板跟进
我们：采集 → 打分卡 → 待投清单 → 话术+闸门 → 确认 → 接管 BOSS 执行 → 三态核验 → 台账/会话
                  ↑ 少一环「逐岗 PDF」              ↑ 多两环「闸门」「L3 送达」
```

三条不能动的设计事实：

1. **BOSS 必须在前台才能读控件树**，而我们自己的界面此时在后台 → **所有执行期操作只能发生在悬浮面板上**。
2. **App 已登录、不需要扫码**，所以不做账号体系、不做云端同步；数据全在本地 SQLite。
3. **每批必须人按一次**，且闸门 9 条规则必须在发送前可见、可改、可解释。

## 3. 信息架构与导航

### 3.1 结构

```
[左] 功能轨 84px：驾驶舱 / 待投 / 话术 / 执行 / 台账 / 会话 / 简历 / 网申 / 设置
[中] 工作区：列表 + 详情双栏（平板横屏的主力形态）
[右] 上下文面板：打分三件套 / 闸门 9 条 / 会话资料（按页面变化）
[上] 全局状态条：BOSS 前台 · 无障碍 · 今日配额 · 通道
[浮] 悬浮面板（系统 overlay）：采集 / 开始 / 暂停 / 进度 / 熔断
```

### 3.2 导航原则

- **左轨只放 7 个目的地**，执行期不靠左轨（那时 App 在后台，左轨点不到）。
- **一条主链**：驾驶舱 → 待投 → 话术 → 确认 → 执行 → 核验；其余页面是旁路。
- **所有「会改 BOSS 状态」的动作只有两个入口**：批次确认页的「确认投递」、悬浮面板的「开始/暂停」。
- **不设二级 Tab 套娃**；列表内用筛选 chip，详情用右侧面板。

### 3.3 7 个模块 / 14 屏

| 模块 | 屏 | 名称 | 核心目的 |

## 4. 模块详设

### M1 今日驾驶舱（S01）

**目标**：把「今天该做什么」压缩成 5 秒可读。

**结构**
- 顶部一句话入口：「帮我找 27 届 Java 实习，广州/深圳，本周活跃」→「解析」→ 跳采集台并预填 chip（F11）。
- 主卡：`今晚 21:00 · 标准档批次` + `6/8 已送达` + 环形进度 + 「继续执行 2 家」。
- 流水线四步：`07:30 采集 30` → `12:30 勾选 8` → `21:00 执行 6` → `21:20 核验`。
- 4 个 KPI：候选 / 待投 / 今日送达 / 真人回复。
- 两条侧栏：今日节奏（时间线）、待跟进（HR 回复 + 面试）。
- 风险条：闸门拦截 2 条 R7 高相似、无障碍授权状态。

**交互**
- 点 KPI 进入对应列表；点「继续执行」跳 S08 并自动唤起浮层。
- 配额 `6/15` 与设置页双向同步。

**异常/空态**
- 未授权无障碍：主卡替换为「先开无障碍」引导卡，按钮直达系统设置。
- 今日无批次：主卡变为「从待投清单里选一批」。

**验收**：3 秒内能回答「现在该点哪」；一屏不滚动。

### M2 采集与待投

#### S02 采集台

**目标**：一次设定，只读采集 30–50 条。

**元素**
- 关键词 chip（Java / 后端 / 全栈 / Java实习），城市（广州 / 深圳），薪资双滑杆 6–15K，经验（经验不限 / 在校应届 / 1 年内），排除词（外包 / 驻场 / 硕士 / 销售 / 3-5年）。
- 数据源：`BOSS App 原生（无障碍）`，可切「网页版降级」。
- 采集深度：5 屏（约 40 条）；「只抓卡片，不进详情」。
- 右侧实时：`23/40 已读 · 第 3 屏 · 命中 12 · 去重 5`，滚动卡片流，底部 run_log。
- 悬浮球预览：`采集中 23`（证明采集发生在 BOSS 前台）。

**交互**
- 开始前校验 BOSS 包名；不在前台则按钮禁用并给「切到 BOSS」。
- 重复率 > 80% 自动停，提示「已到底」。
- 采集完成 → 自动进 S03，并 toast「新增 12 条，去重 5 条」。

**验收**：5 屏 ≥40 条，字段空值率 <10%（PRD F2）。

#### S03 待投清单

**目标**：30 秒勾出 8 家。

**元素**
- 筛选：今日活跃 / 27 届 / 排除已投 / 只看已选；排序：匹配分↓ / 薪资 / 活跃度。
- 行：勾选框 · 岗位/公司 · 薪资 · 福利标签 · HR 活跃度 · 匹配分色块。
- 右侧摘要：候选 32 / 去重命中 5 / 黑名单 2 / 已选 8。
- 底部粘性条：`已选 8 家 · 预计 7 分 30 秒` +「生成话术」。

**交互**
- 勾选即时更新底部；超过当日剩余配额时提示「本批最多 8 家」。
- 单击行进 S04；长按多选（可选，非必须）。

**验收**：30 条里 30 秒勾 8 条（PRD F2.4）。

#### S04 岗位详情 · 打分卡

**目标**：把「投不投」变成一次可解释的判断。

**元素**
- 左：岗位头（岗位/公司/薪资/规模/融资/学历/经验/HR/活跃度/地区），JD 全文，命中词绿色、缺失词红色删除线。
- 右：78 分环形 + 5 维明细（硬性 40 / 技能 22 / 可对证 14 / 公司质量 8 / 时效 5）+ 三件套（优势 / 不足 / 建议）+ `jd_hit 5` / `jd_miss 2`。
- 底部：「加入待投」/「忽略」。

**交互**
- `jd_miss` 在话术工作台变成硬约束（这些词一个字都不许出现）。
- 「不足」与「建议」必须成对出现，禁止只给负面。

**验收**：抽检 20 条，优势必须引用 JD 原文。

### M3 话术与闸门

#### S05 话术工作台

**目标**：8 条话术，逐条可控地过闸。

**元素**
- 左：8 家队列，状态点（已过闸 / 待改 / 未生成）。
- 中：岗位头 + 双版本 Tab（A 技术证据型 / B 业务理解型）+ 引用 JD 原句 + 可编辑正文 + `视觉宽度 82 · 3 句` + 操作「收进队列 / 丢弃 / 下一条」。
- 右：`质量分 88 · A` + 9 条规则清单（R1 宽度 / R2 开场 / R3 JD 引用 / R7 近 7 天相似 / R8 事实库 / R4 数字 / R5 到岗 / R6 技术栈 / R9 结尾）+「全部过闸」。

**交互**
- 编辑即重算分数；硬拦项标红并禁止「收进队列」。
- 每版标注「引用了 JD 哪句」，防止审核疲劳。
- 接近 R7 阈值（0.72–0.90）给黄色提醒，不拦。

**验收**：过闸率 ≥90%，「愿意原样发」≥80%（PRD F4）。

#### S06 闸门逐条修复

**目标**：让用户理解为什么不过，而不是只看到一个红叉。

**元素**
- 左：原稿（问题处下划线 + 编号）与修复稿对照。
- 右：3 条未通过规则的详情：`R7 相似度 0.83（与 10-23 批 #7 相似）`、`R4 缺少带数字结果`、`R9 结尾不是问句`；每条给「一键修复」与解释；顶部 `61 → 89` 预览。
- 底部：「应用全部修复 / 重新生成 / 跳过此岗」。

**交互**
- 一键修复是**改写建议**，必须回填到正文并可继续编辑，不做静默替换。
- R8（事实库外说法）不提供一键修复，只能删除或人工改写——防止 AI 编造。

### M4 批次执行

#### S07 批次确认

**目标**：全流程唯一「必须人按」的闸口。

**元素**
- 左：8 条清单（公司 / 岗位 / 闸门分 / 末 8 字指纹 / 状态），全选可用。
- 右：配额（`6 → 14 / 15`）、去重（0 冲突）、熔断阈值（验证码 / 连续 3 次 wrong_target / 命中率 <50%）、安全阀说明（header 公司名校验 ≥0.75）。
- 确认区：勾选「我已核对 8 条话术」后按钮才亮；文案明确「AI 不会替你点发送」。

**交互**
- 未开无障碍 / BOSS 不在前台 → 按钮禁用并给出原因。
- 超配额自动截断到剩余额度，并显性提示。

#### S08 执行中 · 悬浮面板

**目标**：在 BOSS 前台时，唯一可见的进度与刹车。

**元素**
- 背景：BOSS App（真实前台），顶部状态条 `无障碍运行中`。
- 浮层（右侧 420dp，深色）：`批次 6 · 标准档`、`6/8`、当前公司、`第 4/11 步 · 已点击立即沟通，等待会话`、倒计时 `00:37 后下一条`、`暂停 / 终止`、三行实时日志、`L3 已核验 6 · 失败 0`。
- 折叠球：`6/8`，拖到边缘吸附；熔断时变红并弹全宽横幅。

**交互**
- 所有按钮在浮层内完成（不抢焦点，BOSS 仍是前台）。
- 熔断 → 立即停、截图、冷却 24/48h，浮层显示原因与「今天不再投」。
- 强杀 App 后重进：浮层恢复批次与断点（`从第 7 家继续`）。

#### S09 核验报告

**目标**：用 L1/L2/L3 回答「到底送到了没有」。

**元素**
- 顶部：`L3 送达 6/8`、失败 1、跳过 1、重复 0、平均 51 秒/家。
- 三态漏斗：8 → 7 → 6。
- 表格：公司/岗位 · L1 · L2 · L3 · 指纹校验 · 时间 · 结果。
- 失败详情：`session_not_found` → 会话列表未找到，已跳过；给「手动搜索 / 重试 / 看截图」。

**交互**
- 只有 L3 计为成功；`already_sent` 单独计数，不重复投。
- 失败项重试上限 2 次，超限转人工。

## 5. 电脑端能力在平板上的「不适用」清单

| 能力 | 为什么在平板上不成立 | 替代 |
|---|---|---|
| 浏览器插件 | Android 无扩展机制；且插件是最易被平台识别的形态（PRD A2/A4） | 无障碍主通道 + WebView 降级 + 浮层 |

| 自动提交网申 | 合规红线 | 只代填，人工提交 |

## 7. 状态机与安全阀（设计侧必须表达）

### 7.1 投递状态（PRD §7.2）

```
planned → approved → clicked → bound → delivered → verified
             │           │        │
             └ failed(reason) ──重试≤2──→ approved
                          └─熔断─→ halted
```

UI 映射：S07 只展示 `planned/approved`；S08 展示 `clicked/bound` 的实时迁移；S09 展示终态与失败原因。

### 7.2 批次状态

```
draft → confirmed → running → (paused) → done | halted
```

- `draft`：S07 可改清单；`confirmed` 后清单锁定。
- `running`：只有浮层能暂停/终止；App 主界面显示只读进度。
- `halted`：浮层红色横幅 + 首页风险条，今日不再允许新批次。

### 7.3 安全阀（写进界面，不只写进代码）

1. **header 公司名校验**：S09 失败原因显式列 `wrong_target`，S07 说明「校验不过整条放弃」。
2. **去重**：S03/S07 都显示冲突数；冲突 >0 时不允许确认。
3. **配额**：三处同步，超限自动截断并提示。
4. **熔断**：S08 一键停 + 冷却时间可见。
5. **不代聊**：S11 只提供「填入」，无「自动回复」开关。
