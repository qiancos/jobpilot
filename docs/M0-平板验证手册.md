# M0 · 平板验证手册（半天能做完）

> 目的：在写一行 Android 代码之前，先把「WebView 壳这条路线到底成不成立」变成一个**有证据的结论**。
> 做不完也没关系，但**必须明确记下哪一项没做**——含糊的"应该行"会在两周后变成返工。
---

## 0. 为什么分两条线

> **2026-11-16 更新**：测试 APK 已经构建出来了 →
> `jobpilot/dist/JobPilot-0.1.0-envtest.apk`（781 KB）。
> 所以平板线**优先用这个 App 跑**（它就是一个桌面 UA 的 WebView 壳，还能一键注入自检脚本），
> 比用 Chrome 更接近最终形态。下面用 Chrome 的步骤作为**兜底**保留——万一 APK 装不上（旧系统/厂商限制）再走那条。

真机的 WebView 验证要等壳 App 写出来。在那之前，把能提前验的拆成两条线：

| 线 | 验什么 | 在哪做 | 需要什么 |
|---|---|---|---|
| **平板线** | 网页版在平板上能不能用、会不会被风控 | 平板 Chrome | 平板 + 你的账号 |
| **PC 线** | 你 WORKFLOW 里那套 DOM 选择器还有没有效 | 真实 Edge（已登录） | PC + 现成环境 |

两条线都过 → M1 正式开工。平板线挂了 → 直接走降级通道（PRD §4.2）。

## 1. 平板线（约 20 分钟）

### 准备

1. 平板装 Chrome（系统自带浏览器也行，但优先 Chrome，它的"桌面版网站"更可靠）。
2. **用你平时上网的同一个网络**，不要挂 VPN、不要换代理——换 IP 反而更像异常设备。记下用的是哪个网络，以后固定不变。

### 步骤

| # | 动作 | 记录什么 |
|---|---|---|
| 1 | Chrome 打开 `https://www.zhipin.com`，菜单里勾选**「桌面版网站」** | 页面是 PC 版布局还是被强制跳手机版？截图 |
| 2 | 扫码登录 | 能否登录成功；有没有额外验证（滑块/短信/人脸） |
| 3 | 进 `/web/geek/jobs?query=Java&city=101280100` | 岗位卡片能不能出来？和 PC 上长得一样吗？截图 |
| 4 | 往下翻 3 页 | 有没有跳 `security.html` / 要求验证 / 一直转圈 |
| 5 | 横屏看 | 双栏布局是否可用？要不要缩放？截图（这条决定 UI 设计） |
| 6 | 随便点进一个岗位详情 | 「立即沟通」按钮在不在、可不可点 |
| 7 | 找「今日沟通次数」的入口和文案 | 记下原文（执行引擎要靠它动态判断配额） |

### 判定

- **1–4 全过** → 平板线通过，WebView 大概率可用。
- **第 4 步出现验证/跳转** → 大概率是 UA 或 IP 问题，先换网络再试一次；仍不过 → 平板线判死，走降级。
- **第 5 步很糟**（网页版在平板上难用）→ 仍可做，但 UI 要改成"竖屏为主 + 横屏分栏可选"。

> ⚠️ 风险提示：平板登录可能把你 PC 上的 Edge 踢下线，或触发设备验证。
> **做这一步之前先把 PC 上的 Edge 关掉**，避免两边互踢（PRD §13 R3）。

## 2. PC 线（约 15 分钟）

### 步骤

1. 按 `boss/WORKFLOW.md §2` 启动带调试端口的真实 Edge，登录 BOSS。
2. 打开 DevTools（F12）→ Console。
3. 把 `jobpilot/probe/probe.js` 全文粘进去，回车。
4. 分别在**三个页面**各跑一次：
   - 职位搜索页 `/web/geek/jobs`
   - 岗位详情页 `/job_detail/xxx.html`
   - 聊天页 `/web/geek/chat`
5. 每次把 Console 里那段 JSON 复制出来，存成：
   ```
   jobpilot/probe/result-jobs-YYYYMMDD.json
   jobpilot/probe/result-detail-YYYYMMDD.json
   jobpilot/probe/result-chat-YYYYMMDD.json
   ```

### 看什么

- 每一个检查项是否 `ok: true`，`best` 是哪个选择器。
- `chatDebug.conversationCount` 和 `selfMessageCount` 大于 0 才算聊天页真的读到了。
- `enterDispatchOK` 是否为 true（这只证明**事件通道存在**，不证明能发出去——真发要等壳 App）。

> 脚本是只读的：不点按钮、不发消息。唯一的写操作是往输入框 `dispatchEvent` 一个空 Enter 事件，不会产生内容。

## 3. 判定表

| 平板线 | PC 线 | 结论 | 下一步 |
|---|---|---|---|
| 通过 | 通过 | **A 路线成立** | M1 直接开工：壳 App + WebView + 登录 + 采集 |

| 不通过 | 失效 | 双杀 | 停下来复盘，不要硬上 |
